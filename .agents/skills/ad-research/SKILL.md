# ad-research — 広告のリサーチ

## 使う場面

**依頼主から頼まれたときだけ**です。台本は依頼主が用意するのが既定で、リサーチは標準の工程ではありません。
「競合がどんな広告を出しているか調べてほしい」「訴求の選択肢を出してほしい」と言われたら、このスキルを開きます。
頼まれていないのに始めないでください。時間も、依頼主の待ち時間も増えます。

出来上がるもの: `out/research/<日付>_<商材>.html`（1ファイル。目次・表・画面の写し・出典・検証つき）。
作ったら `open` で依頼主のブラウザに表示します。

## いちばん大事な決まり

**検索エンジンの要約だけで書かないでください。**
実際に起きた事故: AI が「業界をリサーチしました」と報告したが、直接開いたのは当社の LP だけで、
他はすべて検索結果の要約だった。広告ライブラリも透明性センターも開いていなかった。
**広告の実物は、広告のある場所を開かないと見られません。**

だからこのスキルでは、主張ひとつひとつに確かめ方の印を付けます。

| 印 | 意味 |
|---|---|
| `direct`（直接確認） | その URL を自分で開いて、画面で見た |
| `summary`（要約のみ） | 検索結果の要約や第三者の記事で読んだだけ |
| `unknown`（未確認） | 開けなかった・確かめられなかった |
| `inference`（推論） | 事実から考えたこと。**事実ではない** |

**開けなかったものは「未確認」と書きます。** 推測で埋めないでください。
**推論に事実の印を付けないでください。** `research-verifier` がそこを見ます。

## ブラウザで開く（環境によって経路が3つ）

Meta 広告ライブラリと Google 広告の透明性センターは、JavaScript が動かないと中身が出ません。
`curl` や検索では取れません。開いているアプリごとに経路が違います。

| 開いているアプリ | どうやって開くか |
|---|---|
| **Claude**（デスクトップアプリ・Claude Code） | 内蔵のブラウザで開く。画面を撮って `out/research/img/` に保存する |
| **Antigravity** | Browser Subagent に開かせる。撮った画面を同じ場所に保存する |
| **GitHub Copilot ／ ChatGPT** | ブラウザを動かす手段がありません。**依頼主に開いてもらい、画面の写しをもらいます**（下の頼み方） |

3つ目の場合、依頼主に何を見てほしいかを具体的に伝えます（URL と、検索する語と、撮ってほしい画面）。
**渡してもらえなかったものは「未確認」と書きます。** 自分で見ていないものを「確認した」と書かないでください。

ブラウザを動かせない環境で、依頼主にも頼めないときは、**リサーチを引き受けられないことを先に伝えます。**
検索の要約だけで資料を作ってはいけません。

## 手順

### 1. 市場を先に見る（記憶や検索の要約で競合を挙げない）

`knowledge/project.md` を読み、商材・届ける相手・LP・使ってはいけない表現を把握します。
**空欄だらけなら、先に `new-project` を通してください。** 商材と届ける相手が書けていないと、資料を作る `build_research.py` が止まります。

```bash
python3 scripts/check_project.py --for research
```

競合の名前を、自分の記憶や検索エンジンの要約から挙げてはいけません。**先に社名を決めて、あとから広告ライブラリで裏を取る順番も駄目です**（実際に起きた事故: 記憶から挙げた社名のうち、広告を出していない会社が「競合」として資料に残った）。順番は必ず「広告の実物 → 出ていた広告主 → 依頼主が選ぶ」です。**「実際にその市場で広告を出している会社」を一次情報で確かめてから**候補にします。順番:

1. **検索広告の実物**: 届ける相手が打ちそうな語（商材名の一般名詞、悩みの語、「◯◯ 比較」「◯◯ おすすめ」など 5〜10 語）で検索し、**広告枠に出ている広告主**を記録する（社名・見出し・説明文・LP の URL。画面の写しを保存）
2. **Google 広告の透明性センター**（https://adstransparency.google.com/?region=JP ）: 上で見つけた広告主名で検索し、出稿の有無・形式（テキスト／画像／動画）・期間・本数を記録する。商材の語でも検索して、検索広告に出ていない広告主も拾う
3. **Meta 広告ライブラリ**（https://www.facebook.com/ads/library/ 、国＝日本、全広告）: 商材の語・悩みの語で検索し、**現在配信中の広告主**を記録する（本数・開始日・形式）
4. **YouTube**: 商材の語で検索し、広告として出ている動画と、各社の公式チャンネルの広告らしい動画を記録する
5. **市場の規模感と構造**（要約でよい。出典を付ける）: 市場規模、上位のプレイヤー、価格帯、上場企業なら開示資料。ここは [要約のみ] の印で構わない

ここまでを**「市場の見取り図」**として1つの表にします（広告主／出稿している媒体／形式／本数・期間／LP の URL／確認状況）。表を依頼主に見せ、**深掘りする3〜5社を依頼主に選んでもらいます**。依頼主が「他にこの会社も」と言えば足します。AI が勝手に決めて調べ始めないでください。

依頼主が最初から「この会社を調べて」と指定した場合も、上の 1〜4 で**その会社が本当に出稿しているか**を確かめてから深掘りに入ります（出稿していなければ、その事実を伝えて別の候補を提案します）。

決まったら、調べる範囲を1〜2行で言い直して合意を取ります。「見取り図の中からこの4社を、検索広告・画像・動画・LP まで見ます」。

### 2. 一次情報を、自分で開く（ここを飛ばすと全部が崩れます）

各社について、次の5つを**開きます**。開いたら画面を撮り、`out/research/img/` に保存します。

| 開く先 | 何を見るか |
|---|---|
| 各社の LP | 第一画面・オファー・証拠・申し込みの導線。料金の見せ方 |
| **Google 広告の透明性センター** <https://adstransparency.google.com/?region=JP> | 広告主名で検索し、出ている検索広告・画像・動画の**実物**。表示の開始日 |
| **Meta 広告ライブラリ** <https://www.facebook.com/ads/library/> | 国=日本、カテゴリ=すべての広告 で社名を検索。出稿中の広告の実物と期間 |
| 各社サイトの「広告の透明性」相当のページ | ある会社とない会社があります。無ければ「無し」と書く |
| YouTube の公式チャンネル | 動画広告の実物（尺・冒頭・語り手・テロップ・CTA） |

- 数えたもの（本数・期間）は、**数えた画面を撮ってください。** 後で検証役が数え直します
- 一覧が途中で止まる、ログインを求められる、結果が出ない——そういうときは**そのまま「未確認」と書きます**
- 会社の規模感（従業員・資本・広告の本数・出稿期間）は、**取れた事実だけ**。取れなければ空欄のままにします

### 3. 媒体別に整理する

| 媒体 | 押さえる列 |
|---|---|
| 検索広告 | 見出し／説明文 |
| 画像バナー | 訴求／構図 |
| 動画 | 尺／冒頭3秒／語り手／テロップ／CTA |
| LP | 第一画面／オファー／証拠 |

### 4. 枠組みで整理する（順番を守る）

この順に考えます。**できないことを先に確かめてから、何を言うかを決めます。**

1. **非市場の制約**（規制・業種のガイドライン・媒体の審査・取引先のルール）。
   表現の可否はここで決まります。`knowledge/project.md` §4 と突き合わせ、一次情報で確認します
2. **3C** —
   顧客: 誰が・何に困り・**どう探しているか**（検索で探しているのか、紹介や媒体で知るのか。検索需要の大小）。
   競合: 規模感・訴求・媒体・LP・オファーの**実物**。
   自社: LP と提供価値・証拠・弱み
3. **競争の型**を1つ決めます。広告の訴求はこれに従います
   | 型 | 中身 | 広告での意味 |
   |---|---|---|
   | IO型 | 差別化で競争を避ける | 誰も言っていない言い方に立つ。正面の比較に出ない |
   | チェンバレン型 | リソースで勝つ | 本数・予算・制作力で押す。勝てる見込みがあるときだけ |
   | シュンペーター型 | 知と知の結合 | 別の領域の要素を持ち込む |
4. **5F**（**代替品**と**買い手の価格感度**は必ず）。**3行以内**
5. **VRIO の簡易版** — 自社の強みのうち「**広告で証明できるもの**」だけを選びます。
   価値・希少・模倣困難・組織で使えるか、の4つで見て、**画面のどの画で証明するか**まで書きます。
   画面で見せられない強みは、ここに書かないでください

### 5. ターゲットと、媒体ごとの導線を描く

ターゲット像を1〜3人ぶん立て、媒体ごとに**視聴シーン**（いつ・どこで・どんな持ち方で・音は出ているか）を書きます。
感情の流れは **気づき → 関心 → 不安 → 納得 → 行動**。各段で「何がそれを起こすか」と「ここで落ちる理由」を対で書きます。

そのうえで、媒体ごとに1本の導線を描きます。

```
視聴シーン → 感情の流れ → 動画（冒頭・ボディ・CTA）→ 着地 → CV
```

媒体は Meta フィード／リール、YouTube／Demand Gen、TikTok、検索などから、この案件に合うものを選びます。
**全部を並べる必要はありません。** 選ばなかった媒体は、理由を「捨てた案」に書きます。

### 6. 着地は3案を必ず並べる

動画だけを直すのか、LP まで触るのかで、作る動画が変わります。**どれか1つに決め打ちしないでください。**

| 案 | 中身 |
|---|---|
| **A** | 現状の LP のまま（動画を LP に合わせる） |
| **B** | LP を少し直す（**直す箇所を具体的に**: 第一画面・オファー・証拠・フォームのどれか） |
| **C** | 診断フォームや簡易 LP を新設（競合が診断・無料相談型で回しているなら、特に検討する） |

各案に、**期待**（効く理由）・**懸念**（外す理由・規制・工数）・**動画の作り方への影響**（尺・訴求・CTA 文言）を書きます。

### 7. 訴求の選択肢を、冒頭・ボディ・CTA に分けて出す

それぞれに **期待**（効く理由）と **懸念**（外す理由・規制上の注意）を**対で**書きます。
片方しか無いものは、まだ選択肢になっていません。

### 8. まず試す1本を1つ薦め、捨てた案の理由を書く

媒体・尺・冒頭・着地・成果を指定して、1本だけ薦めます。
**何をもって良し悪しを決めるか**も書きます（測る数字）。
選ばなかった案は「捨てた案」に、理由とセットで残します。理由の無い不採用は書かないでください。

### 9. HTML にする

```bash
python3 scripts/build_research.py --print-schema        # 入力 JSON の書式を確かめる
python3 scripts/build_research.py <作った json> --open   # 作って、ブラウザで開く
```

- 入力の見本は `scripts/templates/research.example.json`（すべて架空の商材です）
- 画面の写しは `out/research/img/` に置き、JSON には `"shot": "img/<名前>.png"` と書きます
- 節の並びは固定です。**ファクト → 課題と選択肢 → 意思決定の材料**の順になります

```
1 ファクト（競合と媒体別の実物）   ┬ ファクト
2 3C・競争の型・非市場の制約       ┘
3 ターゲットと視聴シーン           ┬ 課題と選択肢
4 導線設計（媒体別・着地3案）      │
5 訴求の選択肢（冒頭・ボディ・CTA）┘
6 まず試す1本と、捨てた案          ── 意思決定の材料
7 出典と確認状況
8 検証
```

スクリプトは書式の矛盾を落とします。次に当たったら、**回避せず中身を直してください。**

- `direct` と書いたのに、出典の `opened` が `direct` でない → 自分で開いていないということです
- `direct` なのに出典が書かれていない
- 着地の案が3つそろっていない
- 期待と懸念が対になっていない

### 10. 検証を通す（省略できません）

```
research-verifier に、作った HTML のパスを渡す
 → 検証役が、引用された URL を自分で開き直して1件ずつ判定する
 → 返ってきた表を JSON の "verification" に写して、もう一度 build_research.py を走らせる
 → 「一致」以外が残っていたら、本文を直してから検証をやり直す
```

**要修正が残ったまま報告してはいけません。** 判定は4値です。

| 判定 | 意味 | どうするか |
|---|---|---|
| 一致 | 出典にそのとおり書かれている | そのまま |
| 不一致 | 出典と食い違う | 本文を出典に合わせる |
| 出典に記載なし | その出典には書かれていない | 本文から落とすか、印を `summary` / `unknown` に替える |
| 開けない | 検証役も開けなかった | 印を `unknown` に替える |

検証役は**あなたの要約や記憶を使いません。** あなたが「確認しました」と書いたことも信用しません。

### 11. 報告する

- 作った HTML のパスと、ブラウザで開いたこと
- **調べられなかったこと**（未確認の一覧）。ここを隠さないでください
- 検証の結果（合格の件数と、直した件数）
- 次に決めてほしいこと（競合の追加、着地の3案のどれで進めるか、まず試す1本でよいか）

依頼主の言い方は自由です。**貼り付け用の決まり文句を作らないでください。**

## やってはいけないこと

- **記憶から競合名を挙げる。** 市場の見取り図（手順1）を作らずに「候補は A 社・B 社」と言わない。実際に広告を出している会社だけが競合です

- 検索の要約だけで「調べた」と書く
- 開けなかったものを、開いたことにする
- 推論に `direct` の印を付ける（`research-verifier` が落とします）
- 競合を勝手に決めて調べ始める
- 他社の広告の文言を、そのまま台本に写す（参考にするのは構図と訴求の型までです）
- 他社の広告を、数字の根拠にする（`RULES.md` 決まり27。数字は一次情報で裏を取ります）
- 着地を1案だけ出す
- 検証を通さずに報告する
