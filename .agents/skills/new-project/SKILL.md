# new-project — 案件の下ごしらえ

## 使う場面

キットを開いた直後。`knowledge/project.md` が空のまま制作に入ると、禁止表現や出典の漏れが必ず混ざります。**ここを通さずに生成を始めないでください。**

## 手順

### 0. 台本をどう用意するかを選んでもらう（最初の一言）

「台本はもうありますか。それとも一緒に作りますか。訴求から調べて決めますか」と聞き、A（持ち込み）／B（聞き取りから一緒に作る）／C（リサーチしてから作る）を依頼主に選んでもらいます。
AI が勝手に B や C に進んではいけません。A なら聞き取りは商材・禁止表現・必須表記だけに絞り、台本を受け取ります。選んだ結果を `knowledge/CURRENT.md` に書きます。

### 1. 現状を確かめる

- `knowledge/project.md` を読む（空欄か、記入済みか）
- `src/brand.ts` の `BRAND` / `OPERATOR` / `FOOTER_NOTES` / `FONT` を読む
- 依頼文・LP の URL・既存の広告素材をもらえていれば先に読む。**そこから分かることは質問しない**

### 2. 聞き取る（一度に3つまで・専門用語を使わない）

3問ずつ区切って聞きます。相手が言い淀んだら、例を2〜3個出して選んでもらってください。

**第1ラウンド（商材）**
1. 何を売っていますか（名前と、ひとことで言うと何をするものか）
2. 申し込む人はどんな方ですか（状況・困っていること）
3. 動画を見た人に、最後に何をしてほしいですか

**第2ラウンド（言ってはいけないこと）**
4. 使ってはいけない言葉・言い回しはありますか
5. 数字や金額を出すとき、必ず添える注記はありますか
6. 過去に広告の審査で落ちた・注意されたことはありますか

**第3ラウンド（画面に出す表記。必要な場合だけ入れます）**
7. 広告であることの表記（【PR】など）は要りますか。要るなら文言は何にしますか
   （アフィリエイト、第三者の推奨、広告主と表示者が違う——このどれかに当てはまるときは要ります。
   自社が自社の商材を出すだけなら、不要なことがあります）
8. 運営者・広告主の表記は要りますか。要るなら文言は何にしますか
9. 常に出しておきたい注記はありますか（AI 生成素材の注記など）

要否が分からないときは「不要」と決め打ちせず、**根拠（どの規約・どの法令）を調べてから** `knowledge/project.md` §9 に書きます。

必要なら、成果の条件・提携先のルール・使ってよい実績の数値を、さらに3問ずつ追加で聞きます。

### 3. 業種の規制を自分で調べる

聞き取りだけで埋めてはいけません。`knowledge/project.md` §4 の4層（共通の法令／業種の規制／媒体のポリシー／取引先のルール）を、**一次情報で確認して**書きます。根拠の所在と確認日をセットで残してください。「たぶんこうだろう」は書かないでください。

### 4. 書き込む

| 聞いたこと・調べたこと | 書く場所 |
|---|---|
| 商材・届ける相手・伝えたいこと・規制・言ってよいこと・使わない表現・数字の扱い・契約のルール | `knowledge/project.md` |
| 表記（必要な場合のみ）・常時の注記・BGM と音量・フォント | `src/brand.ts`（`BRAND` / `OPERATOR` は不要なら空のまま） |
| 商材名など読み違いが起きる語 | `knowledge/pronunciation.json`（無ければ作る。書き方は `knowledge/project.md` §10） |

- 聞いていないことを想像で埋めないでください。空欄には `（未確認）` と書き、後で聞きます
- 使わない表現は「使わない: ◯◯ → 代わりに: △△」の対で書きます（後で機械的に照合できる形にするため）

### 5. 台本の叩き台を書く前に、3つを聞く

聞き取りが終わっても、**これを聞くまで台本を書かないでください。**
実際に、LP から「誰が画面に出るか」を推し量って決め、冒頭を一般論で書いてしまった事故があります。
**LP に書いてあるのは商材のことで、誰が画面に出るかではありません。**

1. **画面に出るのは誰ですか**（申し込む側の人物／提供する側の人物／人物なしでナレーションだけ）
2. **冒頭は、誰の・どんな場面から始めますか**（見る人がいまどこで何をしているか。時間帯・持ち方・音が出ているか）
3. **最後に何をしてほしいですか**（申し込む／試す／資料を見る／まず知ってもらうだけ）

答えは `knowledge/project.md` §3 に書きます。聞き方は自由です。専門用語を使わず、選択肢を2〜3個出して選んでもらってください。

**答えが返ってこない、または依頼主も決めかねている場合は、台本を書かないでください。**
`ad-research`（競合の広告と視聴シーンを一次情報で調べる）を勧めます。調べてから決めたほうが早くなります。
「たぶん申し込む側の人でしょう」と自分で埋めてはいけません。

### 6. 確認して締める

```bash
python3 scripts/check_project.py --for script   # 聞き取りがファイルに書けているか（空欄があれば止まる）
npm run typecheck
```

`check_project.py` が止まったら、**聞いた答えをファイルに書いてから**もう一度実行します。答えをもらっていない欄は、聞きます。推測で埋めてはいけません。

`src/brand.ts` の編集が壊れていないか確かめます。そのうえで、埋めた内容の要点を**箇条書き10行以内**にまとめて読み上げ、「これで進めてよいか」を確認します。

続けて、**リサーチをするかどうかを依頼主に選んでもらいます**（AI が勝手に始めない。勝手に飛ばさない）。

| 選択肢 | 向いている場合 | かかるもの |
|---|---|---|
| リサーチをしてから台本へ（`ad-research`） | 競合の広告を見たことがない／誰が出るか・冒頭・行動を決めかねている | ブラウザで実物を開くため 30 分〜1 時間の AI の作業時間 |
| リサーチせず台本へ | 台本の材料が揃っている／過去に広告を出していて訴求が決まっている | なし |

選ばれた方を `knowledge/CURRENT.md` に書きます。
最後に `knowledge/CURRENT.md` を更新します。

## 次に使うスキル

上の3つが揃ったら `takes`（セリフつきの映像）または `talking-head`（人が話すだけの映像）へ。揃わないうちは進みません。

競合の広告や訴求のリサーチも頼まれたら、台本に入る前に `ad-research` へ。頼まれていなければ使いません。
