# handoff — 次回に引き継ぐ

## 使う場面

作業を終えるとき。中断するとき。長い作業の区切り。
**次に開いた人（別の AI でも）が `knowledge/CURRENT.md` だけ読めば再開できる**状態にするのが目的です。

## 手順

### 1. 現状を確かめる（推測で書かない）

```bash
git status
```

- `FIXES.md` の、完了の印が付いていない行を数える
- `out/takes-report.json` があれば合格・不合格の数を見る
- `out/takes-ledger.json` で、どのセリフを何回生成したかを見る（回数は台帳が正本。`CURRENT.md` に書き写さない）
- `out/` に書き出し済みの mp4 があるか見る
- `python3 scripts/rehost.py --status` で、公開したままのファイルが無いか見る（あれば `--stop`）

### 2. `knowledge/CURRENT.md` を書き換える

4つの項目を**全部書き直します**（追記して膨らませないでください。常に最新の現在地だけを置きます）。

```markdown
# いまどこまで進んでいるか

## いまの状態
- （例）台本を承認済み。s1〜s6 のテイクを1本ずつ生成し、s4 以外は合格

## 直近でやったこと
- （例）src/scenes.ts に s1〜s3 を配線し、初稿を提示した

## 次にやること
- （例）s4 を、読み方の辞書に「◯◯」を足してから1回だけ作り直す
- （例）指摘 #3（BGM が大きい）に対応する

## 確認待ちのこと
- （例）4:5 の narrowCaptionY が s5 に未設定。書き出し前に必ず入れる
- （例）参照音声の公開URLがまだ届いていない
```

書き方の決まり:

- **次にやること**は「何を」「どのコマンドで」まで書きます。1行1件・多くて5行
- **確認待ちのこと**には、待ち・費用・権限・鍵などの止まっている理由を必ず書きます
- 進捗の言い訳や経緯は書きません。過去は `FIXES.md` に残っています

### 3. 保存するか確かめる

未保存の変更があれば、何を変えたかを1行で伝えて「保存しておきますか」と聞きます。勝手に共有先へ送らないでください。

### 4. 3行で報告する

「今日やったこと / 次にやること / 待っていること」を各1行で伝えて終わります。

## 次に使うスキル

なし。次は `knowledge/CURRENT.md` の「次にやること」に対応するスキルから始めます。
