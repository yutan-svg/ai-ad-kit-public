# fix — 指摘に対応する

## 使う場面

「ここが気になる」「ここを直して」と言われたとき。1件でもこのスキルを通します（口頭で直して報告しないでください）。

## 手順

### 1. 台帳に記録する（直すより先）

`FIXES.md` に**1指摘＝1行**で追記します。言われた言葉を要約しすぎないでください。

| # | 指摘（言われたことをそのまま） | 対応 | 検証方法 | 状態 |
|---|---|---|---|---|

- **同じ指摘が過去にないかを先に検索します。** あれば「なぜ再発したか」を対応欄の1行目に書きます（原因を書かずに直さない）
- 状態欄は空のままにします。完了の印を付けるのは依頼主だけです

### 2. 直す

- 1要素を動かせば周りとの関係が変わります。動かしたシーンは**その場で静止画を出して自分で確かめます**
- 音声の不良は、作り直す前に無コスト救済（`build_chunk.py` / `audio_tools.py cut-gaps`）
- 発音の失敗は、読み方の辞書への登録案を先に出します。辞書に無い語で2回失敗したら、生成を止めて辞書を整えます
- **横展開**: 1箇所直したら、同じ形が他のシーンにないか必ず検索します。同じ形を全部直すまで完了ではありません

### 3. 機械検査（1コマンドずつ）

```bash
npm run align          # 音声を触った・文言を変えたとき
npm run preflight
npm run typecheck
python3 scripts/check_overlap.py <コンポジション名> <フレーム…>   # 配置を動かしたとき
```

`check_overlap.py` は人物の映像で誤検出が出ます。数値が 0 にならないときは `--halo` を広げて測り直し、それでも残るなら「重なっていない」とは報告せず、**数値と所見の両方**を書いてください。

### 4. 第三者の検証（報告の前に・2つとも）

- **`layout-reviewer`**: テロップ・図・人物の配置を変えたら、変更したシーンを審査させます。**合格してから報告**。4:5 も納品対象なら両方のコンポジションで見ます
- **指摘文の原文での逐条確認**: 別のサブエージェントに**依頼主の指摘文の原文**（要約した台帳ではなく原文）を渡し、ファイル・静止画・音声で1件ずつ解決済みか判定させます。解釈違いを拾うのが目的です

一式が仕上がったら `creative-reviewer`（表現と訴求の監査）も通します。

### 5. 報告する

- `FIXES.md` の該当行を表で見せる
- 変更したシーンの静止画を添える
- 直せなかった点・判断が要る点は正直に書く
- 「Studio で確認して、直っていれば `FIXES.md` に印を付けてください」と伝える
- **書き出しはしません**（承諾が出るまで）

## 次に使うスキル

追加の指摘が来たらもう一度 `fix`。承諾が出たら `export`。中断するなら `handoff`。
