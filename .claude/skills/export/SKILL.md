# export — 書き出しと納品

## 使う場面

依頼主が**書き出しに承諾した後だけ**です。承諾が出ていないのにこのスキルを実行しないでください。

## 手順

### 1. 承諾を取って記録する（省略できません）

```bash
python3 scripts/approve.py --composition ad-9x16 --out out/ad-9x16.mp4
```

何を書き出すか（コンポジション・保存先・シーン数・尺・テロップ）を表示して、依頼主に y/N を聞き、記録します。
**この記録をあなたが書いてはいけません**（対話でしか記録できない作りです）。曖昧な返事なら聞き返してください。

記録が無い、別の成果物、または承諾のあとに `src/scenes.ts` を書き換えた——このどれかに当てはまると、
`remotion render` そのものが止まります（`remotion.config.ts` が確認します）。
一度得た承諾は、その成果物にだけ有効です。別のコンポジション・台本を変えた版・冒頭を差し替えた版は、**すべて別の成果物**です。

### 2. 書き出し前の最終確認

```bash
npm run preflight
npm run typecheck
```

指摘への対応を通った動画なら、ここで `layout-reviewer` と指摘文の原文での逐条確認を**1回だけ**通します。一式が仕上がっているなら `creative-reviewer` も通します。

### 3. 書き出す

```bash
npm run render          # out/ad-9x16.mp4
npm run render:4x5      # out/ad-4x5.mp4（4:5 は別の成果物なので、承諾も別に取ります）
```

初回はレンダリング用のブラウザの取得に時間がかかります。
`npx remotion render …` を直接叩いても、承諾の記録が無ければ同じように止まります。

### 4. 成果物を検証する（元のファイルではなく mp4 を見る）

```bash
python3 scripts/verify_render.py out/ad-9x16.mp4 --frames
python3 scripts/audio_tools.py scan-gates out/ad-9x16.mp4 <各シーンの尺をカンマ区切りで>
```

- 完成した mp4 の音声を文字起こしして台本と照合し、各シーンの静止画を出します
- 台本との照合に欠けがあれば納品しません。原因を直して書き出しからやり直します
- シーン境界のクリック音（「プチッ」）が出ていないか確かめます
- 4:5 も納品するなら同じく検証します

### 5. 名前を付けて納品する

命名の決まりは案件ごとに決めます（`knowledge/project.md` §11）。決まっていなければ、次の形を提案してください。

```
<企画名>_<版>_{9x16|4x5}_<案件名>_<YYYYMMDD>.mp4
```

- 日付は**最後に書き出した当日**です。書き出し直したら日付も更新します
- `out/` は Git に入りません。大きなファイルを push せず、共有リンクで渡します
- 納品時に伝えること: ファイル名・尺・比率・検証の結果・気づいている注意点

### 6. 記録する

- `FIXES.md` の未確定の行を整理します（完了の印は自分で付けません）
- `knowledge/assets.md` に、新しく作った映像の印象を1行足します
- `knowledge/CURRENT.md` を更新します
- 生成した分の費用を記録します: `python3 scripts/cost_ledger.py log <タスクID>`

## 次に使うスキル

`handoff`（作業の締め）。別の版を作るなら `takes` に戻ります。
